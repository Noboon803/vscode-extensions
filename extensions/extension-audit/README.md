# Extension Audit

インストール済みの VS Code 拡張機能を、**実行せずに**コードを読んで調べる拡張機能です。確認すべき拡張機能と箇所を絞り込むために使います。インストール手順は、リポジトリのルートにある `README.md` を参照してください。

**検出がなくても、安全であることの証明にはなりません。** このツールは「安全」「危険」を判定せず、見つかった書き方を一覧にするだけです。

## 使い方

1. アクティビティバーの Extension Audit を開きます。
2. `検査を開始` を押します。インストール先の全拡張機能を検査します。コマンドパレットの `Extension Audit: すべての拡張機能を検査` でも実行できます。
3. 確認が必要なものから順に並びます。項目を選ぶと、検出箇所をエディターで開きます。実行ファイルの場合は、Finder などで場所を表示します。

2 回目以降は、VS Code の起動時に新しいバージョンのフォルダを見つけると、そのフォルダだけを自動で再検査します。確認すべき項目が更新で増えていれば通知します。

検査するフォルダは、設定 `extensionAudit.extensionsPath` で変更できます。空の場合は `~/.vscode/extensions` です。

## 検査を省略する

ユーザー設定（`settings.json`）で、検査を省略する拡張機能を指定できます。変更するとすぐに反映されます。

```jsonc
{
  // 開発元の単位で省略する。Marketplace からインストールしたものだけが対象
  "extensionAudit.trustedPublishers": ["ms-python", "ms-dotnettools"],
  // 拡張機能の単位で省略する。自作の VSIX なども対象
  "extensionAudit.excludedExtensions": ["noboon.cheatsheet"]
}
```

省略したものは、一覧の末尾の「検査していない拡張機能」に表示します。

- **開発元 ID:** 拡張機能 ID の `.` より前の部分です。開発元の表示名とは別で、同じ会社でも複数に分かれている場合があります。たとえば、Microsoft は `ms-python`、`ms-vscode`、`ms-vscode-remote`、`ms-dotnettools`、`ms-azuretools`、`ms-ceintl` などに分かれています。
- **完全一致のみ:** `ms-*` のようなワイルドカードは使えません。第三者が似た名前の開発元を登録できる可能性があるためです。
- **インストール元の確認:** 自作の VSIX なら他の開発元を名乗れるので、`trustedPublishers` では、VS Code の記録（`extensions.json`）で Marketplace からのインストールと確認できたものだけを省略します。確認できないものは検査します。
- **ユーザー設定のみ:** リポジトリの `.vscode/settings.json` で検査を無効化されないよう、ワークスペース設定では指定できません。

省略すると、更新の差分も確認できなくなります。開発元のアカウントが乗っ取られた場合や、更新に問題が混入した場合にも気づけません。除外を解除すると再検査しますが、差分の比較元は解除後の検査から始まります。

## 表示の意味

| レベル | 内容 | 例 |
| --- | --- | --- |
| 優先確認 | 検出を避ける書き方や、秘密情報の流出につながる組み合わせ | `require('child' + '_process')`、認証情報のパスと通信が同じファイルにある |
| 要確認 | 強い権限につながる機能。正規の拡張機能でも普通に使う | `child_process`、`eval`、バイナリの同梱 |
| 参考 | 単独では判断材料にならない情報 | URL、通信機能、起動条件 |
| 検査不能 | 構文解析の失敗やサイズ超過などで、中身を確認できていない | 64 MB を超えるファイル |

優先確認は「不正なコード」という判定ではありません。たとえば、Remote SSH のような拡張機能が `.ssh` のパスを持ち、通信もするのは自然です。その拡張機能の役割に合っているかを確認してください。

要約の数字は検出箇所の数ではなく、ルールの種類数です。

## 検査の内容

- **`package.json`:** 自動起動の条件、アンインストール時のスクリプト、一緒に入る拡張機能
- **同梱ファイル:** ネイティブコード、実行ファイル、シェルスクリプト（中身は検査しません）
- **JavaScript（`.js` `.cjs` `.mjs`、`node_modules` を含む）:** 構文解析（`acorn`）で調べます。コメントや文章内の言及には反応しません
  - 外部コマンド、動的なコード実行、通信機能、URL、認証情報や自動実行に使われるパス、環境変数の一括取得
  - 文字列の連結による隠蔽、難読化ツールの変数名、目に見えない Unicode 文字
- **更新の差分:** 以前のバージョンから増えた項目

## できないこと

- 高度な難読化や暗号化されたコード、実行時に外部から取得するコードの内容は分かりません。
- バイナリ、WebAssembly、HTML 内のスクリプトの中身は検査しません。
- 実際に通信するか、何を送信するかは分かりません。コード内の URL や機能の有無が分かるだけです。
- 差分は比較元がある場合だけです。初回の検査で入っているコードは、差分には表示されません。
- VS Code に組み込みの拡張機能、SSH 接続先やコンテナ内の拡張機能は対象外です。
- 省略の判定に使う `extensions.json` と設定は、ユーザー権限で動く別の拡張機能やプログラムなら書き換えられます。

## 安全のための設計

- 検査対象のコードは文字列として読むだけで、実行しません。
- 外部通信はしません。検査対象のフォルダにも書き込みません。結果は VS Code の拡張機能用ストレージに `snapshot.json` として保存します。
- 他の拡張機能を止めないよう、検査は別スレッドで動かします。
- 実行時の依存パッケージは `acorn` だけで、バージョンを固定しています。

このツール自身も検査対象で、`onStartupFinished` で起動するため「参考」として表示されます。

## 開発

必要なもの: Node.js 22 以上、VS Code 1.144 以上

依存パッケージは、リポジトリのルートで `npm install` を実行して入れます。下の表のコマンドはこのフォルダで実行します。

| コマンド | 内容 |
| --- | --- |
| `npm run test:unit` | 検査の中核の単体テストを Node.js で実行（VS Code は不要） |
| `npm test` | 単体テストと統合テストを VS Code 上で実行 |
| `npm run compile` | 型チェック、lint、ビルド |
| `npm run vsix` | `.vsix` パッケージを作成 |

### テストの方針

危険な拡張機能をインストールして確かめることはしません。テストには、検出対象の書き方を含む無害なデータだけを使います。

- `test-fixtures/` のテキストファイルを文字列として読み、解析します。実行はしません。
- フォルダ単位のテストは、一時フォルダに架空の拡張機能を作って行います。インストールはしません。

このため、想定した書き方を検出できることは確認できますが、実在のマルウェアに対する検出率は測定できません。

ルールや判定を変えたら、`src/scanner/rules.ts` の `RULESET_VERSION` を上げます。古い結果と比較して、誤って「増えた」と表示しないようにするためです。

## 構成

- `src/extension.ts` — エントリポイント、コマンド
- `src/auditTree.ts` — 検査結果のビュー
- `src/scanRunner.ts`、`src/scanWorker.ts` — 別スレッドでの検査の実行
- `src/snapshotStore.ts` — 検査結果の保存
- `src/scanner/` — 検査の中核（VS Code に依存しない）
  - `discover.ts` — インストール先の列挙
  - `exclusion.ts` — 検査を省略するものの判定
  - `scanExtension.ts` — フォルダの走査
  - `manifestScanner.ts` — `package.json` の検査
  - `codeScanner.ts` — JavaScript の検査
  - `rules.ts` — ルールの定義
  - `snapshot.ts` — 更新の差分
  - `summary.ts` — 表示用の集計
